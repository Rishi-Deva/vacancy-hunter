## 2. Функциональные требования

### 2.1. Сбор

| № | Требование | Как проверить |
|---|-----------|---------------|
| FR-1 | Система опрашивает каждый включённый источник раз в 3 часа | В `fetch_runs` есть запуск по каждому источнику за каждый интервал |
| FR-2 | Повторно полученная запись не создаёт новую вакансию | Два запуска подряд на тех же данных: число строк `vacancies` не меняется |
| FR-3 | Сбой источника не останавливает остальные и не теряет записи | После восстановления источника вакансии за время сбоя появляются в базе (в пределах 14 дней) |
| FR-4 | Публикации старше 14 дней не сохраняются для анализа | Старый пост не получает статус `pending_llm` |
| FR-5 | Источник в тихом режиме не влияет на отчёт | Вакансия с `quiet_only` = истина не попадает в `report_items` |

### 2.2. Обработка и оценка

| № | Требование | Как проверить |
|---|-----------|---------------|
| FR-6 | Дубли определяются по ссылке, тексту и схожести названия с компанией | Тестовый набор пар из раздела 7 |
| FR-7 | Правила до LLM исключают только по однозначному признаку | Вакансия без технологий профиля в тексте и вакансия со словом Senior в названии доходят до извлечения |
| FR-8 | LLM получает только текст вакансии, словарь навыков и схему. Профиль не передаётся | Проверка содержимого запроса в тесте шлюза |
| FR-9 | Каждый факт имеет цитату и уверенность. Цитата сверяется с текстом | Факт с цитатой, которой нет в тексте, получает значение «неизвестно» |
| FR-10 | Жёсткий фильтр исключает только при подтверждённом «нет» | Вакансия с неизвестной географией получает статус `scored` и пометку «требует проверки» |
| FR-11 | Оценка считается кодом по формулам раздела 11 и воспроизводима | Повторный расчёт на тех же фактах, профиле и правилах даёт тот же балл |
| FR-12 | Каждая оценка ссылается на версию профиля и версию правил | Поля `profile_version_id` и `scoring_version_id` заполнены |
| FR-13 | Предварительная оценка по заголовку хранится и показывается отдельно от полной | Раздел 12 |
| FR-14 | Вакансия hh без описания со словом уровня в названии получает статус `awaiting_description` | Не попадает ни в очередь LLM, ни в отчёт; после появления описания проходит конвейер без дубля |
| FR-15 | При смене профиля или правил оценки пересчитываются без LLM, история сохраняется | Раздел 19 (часть 2) |

### 2.3. Отчёт и интерфейс

| № | Требование | Как проверить |
|---|-----------|---------------|
| FR-16 | Ежедневный отчёт уходит в заданное время (по умолчанию 07:00 Asia/Tbilisi) | Время первой записи `outbox` отчёта |
| FR-17 | В основном блоке только вакансии с полной оценкой не ниже порога, не более заданного числа карточек (1–15) | Состав `report_items` |
| FR-18 | Отчёт не дополняется вакансиями ниже порога. При отсутствии подходящих приходит сводка без карточек | Тест на пустом наборе |
| FR-19 | Вакансия показывается в основном блоке один раз. Пересчёт, повторное получение описания и ручной пересмотр не возвращают её в ежедневный отчёт | Повторный отчёт не содержит вакансий с заполненным `reported_at`; тесты раздела 14.2 |
| FR-20 | Каждая карточка содержит объяснение оценки и пометки «требует проверки» с причиной | Раздел 13 |
| FR-21 | Пользователь может отметить вакансию: интересно, откликнулся, отклонить с причиной | Запись в `feedback_events`, прежние события сохранены |
| FR-22 | Пользователь может вручную пересмотреть оценку, включая отклонённые фильтром | Раздел 18 (часть 2) |
| FR-23 | /today показывает весь состав сегодняшнего отчёта независимо от исхода отправки | Раздел 16 (часть 2) |
| FR-24 | /search ищет по базе и по источникам, не более 20 вызовов LLM на поиск, не блокирует конвейер | Раздел 16 (часть 2) |
| FR-25 | /settings меняет только порог, число карточек, время отчёта и паузу, и подтверждает новое значение | Раздел 16 (часть 2) |
| FR-26 | Бот отвечает только владельцу | Сообщение с другого идентификатора не получает ответа |
| FR-27 | Одно уведомление не отправляется дважды | Раздел 12 ARCHITECTURE.md, тесты `outbox` |

### 2.4. Письма, бюджет, источники

| № | Требование | Как проверить |
|---|-----------|---------------|
| FR-28 | Сопроводительное письмо и ответ на вопрос работодателя готовятся по кнопке и никуда не отправляются автоматически | Нет исходящих запросов, кроме LLM и Telegram владельцу |
| FR-29 | Письмо использует только сведения из текущей версии профиля | Раздел 17 (часть 2) |
| FR-30 | Расход LLM за месяц не превышает жёсткий лимит ($3 по умолчанию), включая параллельные запросы, повторы и длинные тексты | Сумма `llm_ledger` за месяц; тест параллельных резервирований |
| FR-31 | При исчерпании бюджета система продолжает работать без платных вызовов и сообщает причину | Раздел 21 (часть 2) |
| FR-32 | Новый Telegram-канал подключается записью в конфигурации без изменения кода | Добавление канала в тестовой конфигурации |
| FR-33 | Качество каналов измеряется, история проверок сохраняется | Строки `source_checks` |
| FR-34 | Система собирает и оценивает три типа предложений: работа, стажировка, разовый проект или фриланс. Тип указан в каждой карточке. Статистика ведётся раздельно по типам | Разовый заказ без трудоустройства в штат проходит правила и фильтры; в карточке и /stats указан тип |

## 3. Нефункциональные требования

| № | Область | Требование |
|---|---------|-----------|
| NFR-1 | Отклик бота | Бот подтверждает получение любой команды или нажатия не позже чем через 3 секунды. Долгие операции (поиск, письмо, пересчёт, повтор отчёта) выполняются в фоне; подтверждение означает «принято», результат приходит отдельным сообщением |
| NFR-2 | Независимость бота | Ни одна фоновая задача не блокирует обработку команд. Команды не блокируют ежедневный конвейер и отчёт |
| NFR-3 | Своевременность отчёта | Отправка начинается не позже чем через 5 минут после заданного времени |
| NFR-4 | Бюджет LLM | Жёсткий лимит $3 в календарный месяц. Целевой ориентир $0,50–2. Все лимиты настраиваются в `llm.yaml`. Превышение исключено резервированием по верхней границе и ограничением базы |
| NFR-5 | Поведение при исчерпании бюджета | Платные вызовы не выполняются. Продолжают работать: сбор, дедупликация, правила, оценка по заголовку, пересчёт, отчёт по уже оценённым вакансиям, все команды кроме генерации писем. Причина ограничения указывается в сводке отчёта, в /status и в ответе на кнопку «Письмо» |
| NFR-6 | Восстановление | После перезапуска система продолжает работу без ручных действий, без потери данных и без повторных уведомлений |
| NFR-7 | Устойчивость к источникам | Недоступность любого источника не приводит к ошибке отчёта |
| NFR-8 | Воспроизводимость | Оценка однозначно определяется фактами, версией профиля и версией правил |
| NFR-9 | Ресурсы | Приложение и база работают в пределах 1 ГБ памяти и 10 ГБ диска |
| NFR-10 | Безопасность | Секреты только в файле окружения на сервере. Внешний текст не исполняется как инструкция. Ссылки в карточках только из записей источников |
| NFR-11 | Сопровождение | Изменение весов, порогов, списков слов, каналов и расписания не требует правки кода |
| NFR-12 | Изоляция | Система не обращается к коду, базе, токену, сессии и службе соседнего проекта на том же сервере |
| NFR-13 | Наблюдаемость | Состояние источников, задач и бюджета доступно по /status без входа на сервер |

## 4. Файлы конфигурации

Семь файлов в каталоге `config/` хранятся в репозитории. Секреты хранятся отдельно в файле окружения и в репозиторий не попадают.

| Файл | Содержание | Что происходит при изменении |
|------|-----------|-------------------------------|
| `profile.yaml` | Профиль кандидата (раздел 5) | Новая строка `profile_versions`, пересчёт оценок |
| `skills.yaml` | Словарь навыков (раздел 6) | Входит в версию профиля: новая версия, пересчёт |
| `scoring.yaml` | Веса, штрафы, пороги, правила фильтров и отсева, перечни слов | Новая строка `scoring_versions`, пересчёт |
| `sources.yaml` | Источники: код, тип, адрес, запросы, паузы, начальный режим | Применяется при следующем запуске сбора |
| `retention.yaml` | Сроки хранения | Применяется при следующей очистке |
| `schedule.yaml` | Расписание задач и часовой пояс | Применяется при перезапуске |
| `llm.yaml` | Для каждой роли: идентификатор модели, версия промпта, цены, дата проверки цен, ограничения входа и выхода, лимиты бюджета | Применяется при перезапуске. Смена модели или версии промпта извлечения меняет ключ кэша |

Файл окружения: токен бота, идентификатор владельца, ключ API LLM, параметры подключения к базе, адрес внешнего пульса, после одобрения — данные приложения hh.

### 4.1. Поля `scoring.yaml`

| Группа | Поля |
|--------|------|
| Веса критериев | Максимумы пяти критериев (30, 25, 20, 15, 10) |
| Стек | Доля обязательных и желательных навыков (0,8 и 0,2), вес смежного навыка (0,5), значение при отсутствии навыков в вакансии |
| Задачи | Вес основной и второстепенной задачи (2 и 1), значение при отсутствии задач |
| Уровень и стаж | Границы интервалов и штрафы, штраф за невыполнимое требование и его предел |
| Направление | Баллы категорий (15, 8, 0) и состав категорий |
| Ясность условий | Баллы за каждое подтверждённое условие |
| Поправки | Значения за свежесть и географию, общий предел ±5 |
| Категории | Границы 85, 70, 50 |
| Жёсткие фильтры | Порог лет для исключения (5), перечни признаков для фильтров |
| Отсев до LLM | Перечень несовместимых профессий, признаки «не вакансия», предельный возраст публикации |
| Слова уровня | Senior, Lead, Principal, Architect, Head, Staff, «ведущий», «старший», «руководитель», «главный», «тимлид». Учитывается контекст, а не буквальное совпадение (раздел 11.3) |
| Предварительная оценка | Базовые значения и потолок 69 |
| Отчёт | Значения по умолчанию: порог 50, карточек 15, не более 3 от компании, срок ожидания 3 дня |

### 4.2. Настройки, изменяемые из Telegram

Хранятся в `app_state`, а не в файлах. Имеют приоритет над значениями по умолчанию.

| Настройка | Диапазон | По умолчанию |
|-----------|----------|--------------|
| Порог показа | 50–90 | 50 |
| Максимум карточек в основном блоке | 1–15 | 15 |
| Время отчёта | Любое, с шагом 5 минут | 07:00 |
| Пауза | Включена или выключена | Выключена |

Изменение порога и числа карточек действует на следующие отчёты. Оно не удаляет, не отклоняет и не меняет статус ранее сохранённых вакансий.

Профиль, словарь навыков и правила скоринга из Telegram не меняются.

Заданы владельцем отдельно от резюме. Используются жёсткими фильтрами и критерием «Ясность условий».

| Параметр | Значение |
|----------|----------|
| Текущее место нахождения | Грузия |
| Предпочтительный формат | Удалённая работа или удалённая стажировка |
| Возможность работы из Грузии | Проверяется по условиям каждой вакансии. Не предполагается заранее |
| Право на официальное трудоустройство в конкретной стране | Неизвестно. Не считается подтверждённым ни для одной страны |
| Приоритет географии работодателя | Россия, Казахстан, затем другие страны СНГ. Международные вакансии допустимы при отсутствии языковых и юридических ограничений |
| Рабочий язык | Русский |

## 6. Словарь навыков

Словарь нужен, чтобы сопоставление вакансии с профилем выполнял код, а не LLM.

| Элемент | Описание |
|---------|----------|
| Каноническое название | Одно имя навыка: `postgresql`, `fastapi`, `pytest` |
| Синонимы | Варианты написания: «Postgres», «PostgreSQL», «Постгрес» |
| Группа | Область из раздела 5.2 или «вне профиля» |
| Смежные навыки | Навыки, владение которыми частично закрывает требование |

Правила:

- LLM получает перечень канонических названий и возвращает навыки вакансии в этом виде. Навык, которого нет в словаре, возвращается исходным текстом.
- Навык вне словаря считается отсутствующим и записывается в журнал. Раз в месяц владелец получает список частых неизвестных навыков для пополнения словаря.
- Смежность задаётся только явно и в одну сторону: «требуется X, в профиле есть Y».

Начальный перечень смежных пар (вес 0,5):

| Требуется в вакансии | Засчитывается при наличии в профиле |
|----------------------|--------------------------------------|
| Django, Flask, aiohttp | FastAPI |
| MySQL, MariaDB | PostgreSQL |
| aiogram 2, python-telegram-bot, pyTelegramBotAPI | aiogram 3 |
| Scrapy, BeautifulSoup, Selenium для сбора данных | Веб-скрапинг (curl_cffi, Apify) |
| GitLab, Bitbucket | Git, GitHub |
| Insomnia, другие клиенты API | Postman |
| YandexGPT, GigaChat, другие LLM API | Claude API, OpenAI API |
| LangChain, LlamaIndex | RAG, LLM-интеграции |

Словарь включает и навыки вне профиля (например, Kubernetes, Kafka, Selenium для UI-тестов, Playwright, Jira): они нужны, чтобы точно показывать недостающее.

## 7. Дедупликация

Проверка выполняется для каждой новой вакансии до правил и до LLM, уровни идут по порядку.

| Уровень | Признак | Окно поиска | Примечание |
|---------|---------|-------------|------------|
| 1 | Совпадает каноническая ссылка | 365 дней | Ссылка из поста Telegram приводится к виду ссылки сайта: без параметров отслеживания, с единым доменом |
| 2 | Совпадает хеш нормализованного текста | 365 дней | Нормализация: нижний регистр, без пробельных различий, эмодзи и хештегов |
| 3 | Совпадает нормализованная компания и схожесть названий не ниже 0,85 | 30 дней | Не применяется, если компания не определена |

Действия при совпадении:

- новая запись получает статус `duplicate` и ссылку на оригинал; её источник добавляется оригиналу в `vacancy_sources`;
- если у оригинала нет описания, а у дубля есть, описание переносится оригиналу и он проходит полный конвейер;
- если оригинал известен только из тихих источников, а дубль пришёл из активного, признак `quiet_only` снимается;
- дубль ранее показанной или отклонённой пользователем вакансии повторно не показывается;
- на уровне 3 за пределами 30 дней повторная публикация считается новой вакансией.

Проверочные пары для FR-6: одна вакансия с сайта и её пересказ в канале со ссылкой; один и тот же пост в двух каналах; одна компания с названиями «Python-разработчик» и «Разработчик Python (удалённо)»; две разные вакансии одной компании («QA-инженер» и «Python-разработчик») — не дубли.

## 8. Правила до LLM

Назначение — не тратить бюджет на заведомо непригодные записи. Правило исключает только при однозначном признаке. При сомнении вакансия идёт на извлечение.

| Код причины | Условие исключения |
|-------------|--------------------|
| `too_old` | Публикация старше 14 дней |
| `not_vacancy` | Явные признаки не вакансии: хештег или заголовок «резюме», «ищу работу»; реклама курса или канала без описания должности; подборка ссылок без текста вакансии |
| `incompatible_role` | Название прямо называет профессию из перечня несовместимых: бухгалтер, юрист, дизайнер, менеджер по продажам, 1С-программист, Java-разработчик, C#-разработчик, PHP-разработчик, iOS-разработчик, Android-разработчик, frontend-разработчик и подобные |
| `office_only` | Структурное поле источника однозначно указывает на работу в офисе |
| `empty` | Текст короче 80 знаков и нет ссылки на вакансию |

Чего правила не делают:

- не исключают разовые проекты и фриланс-заказы: отсутствие трудоустройства в штат признаком не является;
- не исключают за слова уровня в названии;
- не исключают за отсутствие технологий профиля в тексте;
- не исключают по ключевым словам в теле текста: упоминание Java или продаж в описании не является признаком;
- не применяют особых условий к отдельным каналам.

Если название содержит и несовместимую профессию, и слово из профиля («Java/Python-разработчик»), правило `incompatible_role` не срабатывает.

Вакансия, прошедшая правила, получает статус `pending_llm`. Исключение: вакансия без описания (раздел 12).

## 10. Жёсткие фильтры

Восемь фильтров из ARCHITECTURE.md, раздел 9.1. Каждый возвращает «да» (пройден), «нет» или «неизвестно».

Общие правила:

- «нет» ставится только по факту с проверенной цитатой и уверенностью не ниже средней;
- «неизвестно» никогда не исключает вакансию. Оно даёт пометку «требует проверки» с указанием причины и, как правило, ноль баллов за соответствующее условие в критерии «Ясность условий»;
- одно «нет» даёт статус `rejected_gate`. Баллы всё равно считаются и сохраняются для ручного пересмотра;
- структурное поле источника используется наравне с фактом. При противоречии с текстом ставится «неизвестно».

| Фильтр | «Нет» | «Неизвестно» | «Да» |
|--------|-------|--------------|------|
| Формат | Только офис; обязательный гибрид; обязательный переезд | Формат не указан | Удалённая работа указана явно |
| География | Явное требование находиться в конкретной стране или городе, которому работа из Грузии не соответствует | География не указана; формулировка «удалённо по РФ» и подобные без прямого требования присутствия | Любая страна; перечень, включающий Грузию; страны СНГ и зарубежье разрешены явно |
| Язык | Обязательно разговорное, свободное или письменное владение языком, которого нет в профиле (в том числе английским) | Язык упомянут без уровня или без ясной обязательности | Языковых требований нет; иностранный язык желателен; требуется только чтение технической документации. Язык текста вакансии значения не имеет |
| Документы | Обязательное требование совпадает с записью списка «подтверждённо отсутствующее» | Любое требование к документам, телефону или форме оформления, пока параметры профиля неизвестны | Требований нет |
| Уровень | Обязательный стаж от 5 лет, независимо от названия должности | Стаж упомянут, но неясно, обязателен ли он | Стаж меньше 5 лет, желательный или не указан |
| Характер работы | Продажи, холодные звонки, активные переговоры, презентации или поиск клиентов — основная часть работы | Такие задачи есть, их доля неясна | Таких задач нет или они второстепенные |
| Достоверность | Не вакансия; оплата со стороны кандидата; запрос платёжных данных | Слабые признаки: нет названия компании и описания обязанностей одновременно | Признаков нет |
| Актуальность | Источник сообщил о закрытии; пост удалён; срок приёма откликов истёк | Проверить невозможно | Вакансия открыта |

Уточнения к фильтру «Уровень»:

- слова Senior, Lead и подобные в названии фильтр не учитывает. Они влияют только на штраф (раздел 11.3);
- желательный стаж любой длительности не исключает;
- руководящие и старшие обязанности без требования стажа отражаются через типы задач («Управление людьми» не покрыто профилем), а не через фильтр.

Уточнение к фильтру «Документы»: до заполнения параметров профиля фильтр не может вернуть «нет».

## 11. Скоринг

### 11.1. Порядок расчёта

1. Жёсткие фильтры (раздел 10).
2. Пять критериев, каждый независимо, результат в пределах от 0 до максимума критерия.
3. Сумма критериев: от 0 до 100.
4. Поправки (раздел 11.7): от −2 до +4.
5. Ограничение итога диапазоном 0–100.
6. Категория (раздел 11.8).

Правило одного штрафа — каждый недостаток учитывается в одном критерии:

| Недостаток | Единственный критерий |
|------------|------------------------|
| Отсутствует требуемый навык | Стек |
| Задачи не совпадают с проектами | Опыт и задачи |
| Требуемый стаж, слово уровня в названии | Уровень и стаж |
| Подтверждённо невыполнимое требование, не являющееся навыком | Уровень и стаж |
| Неизвестное или неподтверждённое условие работы | Ясность условий |

Требование, учтённое как навык, не считается «прочим обязательным требованием». Управленческие обязанности учитываются только в задачах.

### 11.2. Стек — 30 баллов

Покрытие одного навыка: 1 — есть в подтверждённых; 0,5 — закрыт смежным; 0 — отсутствует, не найден в словаре или «требует подтверждения».

| Что указано в вакансии | Формула |
|------------------------|---------|
| Обязательные и желательные навыки | 30 × (0,8 × среднее покрытие обязательных + 0,2 × среднее покрытие желательных) |
| Только обязательные | 30 × среднее покрытие обязательных |
| Только желательные | 15 + 15 × среднее покрытие желательных |
| Навыки не указаны | 15 и пометка «навыки не указаны» |

Результат округляется до целого.

### 11.3. Уровень и стаж — 20 баллов

Начальное значение 20. Штраф за стаж один, по первой подходящей строке:

| Порядок | Условие | Штраф |
|---------|---------|-------|
| 1 | Обязательный стаж от 5 лет | Не применяется: вакансия исключена фильтром |
| 2 | Обязательный стаж от 3 лет до менее 5 лет | −12 |
| 3 | Обязательный стаж от 1 года до менее 3 лет | −4 |
| 4 | Стаж не указан, и старший или руководящий уровень подтверждён (см. ниже) | −6 |
| 5 | Стаж не указан и нет слова уровня; стаж только желательный; обязательный стаж менее 1 года | 0 |

Когда уровень считается подтверждённым для строки 4:

| Ситуация | Условие |
|----------|---------|
| Описание есть | Извлечённый факт «уровень по тексту» равен «старший» или «руководящий», с проверенной цитатой и уверенностью не ниже средней. Совпадение слова в названии без такого факта штрафа не даёт |
| Описания нет | Слово уровня в названии относится к названию роли: «Senior Python Developer», «Ведущий тестировщик». Слово в другом значении («помощник руководителя», «главный офис») не учитывается |

Штрафы за стаж не суммируются. Слово уровня при указанном стаже отдельно не штрафуется: Senior с обязательными 3–5 годами получает только −12.

Дополнительно: −3 за каждое прочее обязательное требование, невыполнимость которого подтверждена списком «подтверждённо отсутствующее» (раздел 5.6), но не более −9 в сумме. Требование, по которому сведений в профиле нет, невыполненным не считается и уходит в пометки «требует проверки».

Критерий не опускается ниже 0.

### 11.4. Направление — 15 баллов

| Основное | 15 | Python-разработка и backend; FastAPI и REST API; Telegram-боты; AI-разработка, AI-ассистенты и LLM; интеграции с внешними сервисами и API; автоматизация процессов и техническая автоматизация разработкой; QA: ручное тестирование, тестирование API, автоматизация тестирования; сбор данных и скрапинг; технические стажировки и разовые проекты по этим направлениям |

### 11.5. Опыт и задачи — 25 баллов

Формула: 25 × (сумма весов покрытых задач) ÷ (сумма весов всех задач). Вес основной задачи 2, второстепенной 1. Задача покрыта, если её тип есть в левом столбце раздела 9.2.

Если задачи в вакансии не описаны: 12 баллов и пометка «задачи не описаны».

### 11.6. Ясность условий — 10 баллов

Баллы начисляются за сведения, которые явно указаны в вакансии и подтверждены цитатой. За неуказанное условие начисляется 0 без дополнительного штрафа.

| Условие | Баллы | За какие сведения начисляются | Когда 0 |
|---------|-------|-------------------------------|---------|
| Удалённый формат | 4 | В тексте или структурном поле прямо указана удалённая работа | Формат не указан или указан противоречиво |
| География | 3 | Прямо разрешена работа из любой страны, из-за рубежа, из стран СНГ или из перечня, включающего Грузию | География не указана; формулировки вида «удалённо по РФ» без прямого разрешения работы из-за рубежа |
| Оформление | 2 | Способ оформления и оплаты описан и не содержит требований к документам, телефону или счёту, по которым сведений в профиле нет | Способ не описан либо содержит требование со статусом «требует проверки» |
| Рабочий язык | 1 | Указан русский язык работы, либо вакансия на русском без языковых требований, либо иностранный язык только желателен | Язык упомянут без ясной обязательности |

Сумма по критерию — от 0 до 10.

### 11.7. Поправки

Возраст вакансии считается в полных сутках от даты публикации до момента расчёта. Если источник не дал дату публикации, берётся дата первого обнаружения.

| Поправка за свежесть | Возраст вакансии | Значение |
|----------------------|------------------|----------|
| Свежая | 0–2 суток | +2 |
| Обычная | 3–7 суток | 0 |
| Давняя | 8–14 суток | −2 |

Страна работодателя берётся из структурного поля источника, при его отсутствии — из извлечённого факта с проверенной цитатой.

| Поправка за географию | Страна работодателя | Значение |
|-----------------------|---------------------|----------|
| Первый приоритет | Россия или Казахстан | +2 |
| Второй приоритет | Другие страны СНГ | +1 |
| Без поправки | Любая другая страна; международная компания без указания страны; страна не определена | 0 |

Сумма поправок лежит в пределах от −2 до +4 и не выходит за согласованный диапазон ±5. При изменении значений в конфигурации проверка при загрузке отклоняет набор, в котором сумма может выйти за ±5. Зарплата в оценке не участвует ни в каком виде. Поправки показываются в объяснении отдельной строкой.

### 11.10. Типы предложений

Тип предложения определяется из фактов и не является критерием оценки: баллов за тип нет.

| Тип | Когда присваивается | Подпись в карточке |
|-----|---------------------|--------------------|
| Работа | Постоянная или временная занятость, полная или частичная | «Работа» |
| Стажировка | Стажировка, в том числе неоплачиваемая: это указывается отдельной пометкой | «Стажировка» |
| Разовый проект | Проектное задание, фриланс-заказ, оплачиваемая техническая задача без занятости | «Разовый проект / фриланс» |
| Не определён | Из текста тип не ясен | «Тип не определён» |

Правила для разовых проектов:

- оцениваются теми же пятью критериями, жёсткими фильтрами и поправками. Отсутствие трудоустройства в штат не является недостатком и не штрафуется;
- критерий «Стек» считается по требуемым технологиям заказа, «Опыт и задачи» — по задачам заказа, «Уровень и стаж» — по требованиям к исполнителю, если они указаны;
- в критерии «Ясность условий» строка «Оформление» (2 балла) для проекта начисляется, если описаны порядок оплаты и срок или объём работ и нет требований к документам или счёту со статусом «требует проверки». Остальные строки без изменений;
- фильтр «Достоверность» дополнительно даёт «нет» при требовании предоплаты или залога со стороны исполнителя;
- бюджет проекта, как и зарплата, в оценке не участвует и показывается в карточке;
- в оценке по заголовку тип определяется по названию, когда это возможно, иначе «не определён».

Показ и статистика:

- три типа показываются в общем основном блоке отчёта с общим лимитом и общей сортировкой по баллу, каждая карточка начинается с подписи типа. Показ можно отфильтровать по типу (раздел 16.6);
- сводка отчёта, /stats, ежемесячная сводка и статистика источников дают показатели раздельно по типам. Суммарные показатели без разбивки не приводятся;
- размеченная выборка для приёмки (раздел 24.2) включает не менее 5 разовых проектов.

## 12. Предварительная оценка по заголовку

Применяется к вакансиям без описания (сейчас — hh через RSS). Общие правила режима — в SOURCES.md, раздел 5.1.

### 12.1. Развилка после правил до LLM

| Ситуация | Статус | Дальнейшее |
|----------|--------|-----------|
| Слово уровня в названии относится к названию роли (раздел 11.3) | `awaiting_description` | Не оценивается, не показывается, не отклоняется, не удаляется. Ждёт полного описания |
| Слова уровня нет | `scored` с оценкой вида «предварительная» | Может попасть в блок «Только по заголовку» |

`awaiting_description` — состояние обработки, а не оценка соответствия кандидату.

### 12.2. Расчёт

LLM не вызывается. Направление определяется по названию должности по перечням ключевых слов из `scoring.yaml`: отдельный перечень для основного и для смежного направления.

| Базовое значение | Условие присвоения |
|------------------|--------------------|
| 65 | Название относится к основному направлению и содержит указание на начальный уровень: «стажёр», «intern», «junior», «начинающий», «без опыта», «trainee» |
| 58 | Название относится к основному направлению, указаний на уровень нет |
| 50 | Название относится к смежному направлению |
| 40 | Направление по названию не определено или относится к прочему. Вакансия не показывается |

Если название подходит под несколько строк, берётся первая сверху. Вакансии со словом старшего уровня сюда не попадают: они получают статус `awaiting_description` (раздел 12.1).

К базовому значению прибавляются поправки раздела 11.7 по тем же условиям. Итог ограничен сверху значением 69. Категория — только «можно рассмотреть» или «скрыто».

Жёсткие фильтры в этом режиме работают только по структурным полям ленты. Остальные получают «неизвестно».

### 12.3. Разделение с полной оценкой

- Отдельный блок отчёта, не более 5 карточек в день, по убыванию предварительного балла.
- В общей сортировке, в лимите основного блока и в статистике основного блока не участвует.
- В каждой карточке пометка: «Оценка только по заголовку, полное описание не проверено».
- Пересчёт при смене правил выполняется и для предварительных оценок, по тем же правилам истории.

### 12.4. Переход к полной обработке

После получения токена приложения hh:

1. Для вакансий со статусом `awaiting_description` и для открытых вакансий с предварительной оценкой запрашивается описание по идентификатору, уже сохранённому в `vacancy_sources`.
2. Описание записывается в существующую строку вакансии. Новая строка не создаётся, дедупликация раздела 7 выполняется по появившемуся тексту.
3. Вакансия получает статус `pending_llm` и проходит обычный конвейер.
4. При неудаче запроса статус не меняется, в `status_reason` записывается причина, фиксируется время попытки. Повтор — при следующем запуске, не чаще раза в сутки.
5. Если источник сообщил, что вакансия закрыта, статус меняется на `closed`.
6. Вакансия, уже показанная по заголовку, после полной оценки в ежедневный отчёт не возвращается при любом балле. Владелец получает одно уведомление о дооценке со списком по кнопке (раздел 15.4).
7. Вакансия, которая не показывалась ни разу (в том числе из `awaiting_description`), может войти в основной блок на общих основаниях, если выполнены три условия раздела 14.2.

### 13.2. Шаблоны вывода

| Условие | Текст |

Сильнейшие причины и риски выбираются из критериев с наибольшей и наименьшей долей набранных баллов.

### 13.3. Подробный вид

Открывается кнопкой «Подробнее». Дополнительно показывает:

- состояние каждого из восьми фильтров с цитатой из вакансии;
- полный список обязательных и желательных навыков с отметкой: есть, смежный, нет, требует подтверждения;
- задачи вакансии и проекты профиля, которые их закрывают;
- применённый штраф за стаж и его основание;
- особые требования к отклику и текст, обращённый к ИИ, если они найдены;
- уверенность извлечения: число фактов с высокой, средней и низкой уверенностью, число фактов, пониженных до «неизвестно» из-за непроверенной цитаты;
- версии профиля и правил, по которым посчитана оценка; состояние оценки, если оно отличается от «актуальная»;
- источники, в которых найдена вакансия.

### 13.4. Ограничения отображения

- Весь текст из вакансии и из фактов экранируется перед отправкой.
- Цитаты обрезаются до 200 знаков.
- Сообщение не превышает предела Telegram: при нехватке места сокращаются строки 7 и 6, затем 5.

## 14. Актуальность и свежесть

### 14.1. Даты вакансии

| Дата | Откуда берётся | Меняется ли |
|------|----------------|-------------|
| Дата публикации | Из источника. Если источник её не даёт, равна дате первого обнаружения | Нет |
| Дата первого обнаружения | Момент первого сохранения вакансии | Нет |
| Дата первой полной оценки | Момент, когда вакансия впервые получила оценку вида «полная» | Нет. Фиксируется один раз |
| Отметка о показе в основном блоке | Момент первого включения в основной блок отчёта | Нет. Ставится один раз |

### 14.2. Правило первого показа

Вакансия включается в основной блок ежедневного отчёта только при выполнении всех трёх условий:

1. Отметка о показе в основном блоке пуста.
2. С даты первой полной оценки прошло не более 3 дней.
3. С даты публикации прошло не более 14 дней.

Вакансия, не показанная в этом окне, в ежедневный отчёт больше не попадает. Она остаётся в базе: доступна через /search, участвует в пересчёте, статистике и ручном пересмотре.

Что не меняет дату первой полной оценки и отметку о показе:

| Операция | Дата первой полной оценки | Отметка о показе | Может вернуть вакансию в ежедневный отчёт |
|----------|---------------------------|------------------|--------------------------------------------|
| Пересчёт оценок при смене профиля или правил | Не меняется | Не меняется | Нет |
| Повторное извлечение при смене промпта или модели | Не меняется | Не меняется | Нет |
| Повторное получение описания (hh после токена) | Ставится, если полной оценки ещё не было | Не меняется | Нет для уже показанных по заголовку (раздел 15.4). Да для ни разу не показанных, если выполнены три условия |
| Ручной пересмотр оценки | Не меняется | Не меняется | Нет. Карточка показывается в ответ на действие (раздел 18) |
| Новая публикация той же вакансии, распознанная как дубль | Не меняется | Не меняется | Нет |
| Изменение порога показа | Не меняется | Не меняется | Нет для вакансий за пределами окна |

### 14.3. Проверка актуальности перед отчётом

Проверяются только вакансии, отобранные в отчёт, не более 20 запросов за запуск, общий предел времени 2 минуты.

| Источник | Способ | Результат при невозможности |
|----------|--------|------------------------------|
| API с признаком архива | Запрос вакансии по идентификатору | «Неизвестно» |
| Telegram-канал | Повторный запрос поста. Способ уточняется на шаге A7 | «Неизвестно» |
| RSS | Проверка не поддерживается | «Неизвестно» без пометки в карточке |

Закрытая вакансия получает статус `closed` и в отчёт не попадает. Ошибка проверки не задерживает отчёт: вакансия показывается с пометкой «актуальность не проверена».

### 14.4. Срок приёма откликов

Если в фактах есть срок и он истёк, вакансия получает статус `closed`. Если срок истекает в течение 2 дней, в карточке ставится пометка «срок отклика до …».

## 15. Отбор в отчёт

### 15.1. Основной блок

1. Берутся вакансии со статусом `scored`, с действующей полной оценкой, прошедшие жёсткие фильтры, не из источников в тихом режиме, удовлетворяющие правилу первого показа.
2. Оставляются вакансии с баллом не ниже порога показа. Действующая ручная правка «свой балл» заменяет расчётный балл.
3. Исключаются вакансии с пользовательской отметкой «отклонено».
4. Сортировка: балл по убыванию; при равенстве — более поздняя дата публикации; затем приоритет географии.
5. От одной компании берётся не более 3 вакансий.
6. Берётся не более заданного числа карточек (1–15).
7. Отобранные проходят проверку актуальности (раздел 14.3).

Вакансии, не вошедшие из-за лимита, остаются кандидатами на следующие дни, пока действует правило первого показа.

### 15.2. Блок «Только по заголовку»

Вакансии с предварительной оценкой не ниже 50, не показанные ранее в этом блоке, не старше 14 дней с публикации. Не более 5 в день, после основных карточек, с обязательной пометкой.

### 15.3. Сводка

Отправляется всегда, первым сообщением. Содержит: дату; число карточек в каждом блоке с разбивкой по типам предложения; число собранных, новых, отклонённых правилами и фильтрами вакансий за сутки; число ожидающих анализа; недоступные и деградировавшие источники; остаток бюджета; число неподтверждённых сообщений прошлого отчёта; предупреждения. Если подходящих вакансий нет, сводка сообщает об этом и карточек не содержит.

### 15.4. Уведомление о дооценке

После получения описаний для вакансий hh, ранее показанных по заголовку, такие вакансии в ежедневный отчёт не возвращаются при любом балле. Когда обработка пакета завершена, владелец получает одно сообщение: «Дооценено N вакансий, из них M получили 70 и более баллов» с кнопкой «Показать». Кнопка открывает список дооценённых вакансий с полными оценками, по убыванию балла. Уведомление отправляется не чаще одного раза в сутки.

### 15.5. Изменение порога и числа карточек

Новое значение действует со следующего отчёта. Ранее сохранённые вакансии не удаляются, не отклоняются и их статусы не меняются. Вакансии за пределами окна первого показа после снижения порога в отчёт не возвращаются.

## 16. Telegram-интерфейс

### 16.1. Общие правила

- Бот работает в режиме long polling и отвечает только владельцу.
- Любая команда и любое нажатие подтверждаются не позже чем через 3 секунды. Долгая операция запускается в фоне, результат приходит отдельным сообщением.
- Повторное нажатие той же кнопки не создаёт второго события: бот отвечает «уже отмечено».
- Все исходящие сообщения идут через `outbox`.
- Предпросмотр ссылок отключён. Карточки отчёта, кроме сводки, отправляются без звука.

### 16.2. Команды

| Команда | Поведение |
|---------|-----------|
| /start | Краткое описание системы, список команд, время следующего отчёта |
| /today | Сегодняшний отчёт целиком из `report_items`: сводка и карточки обоих блоков, включая сообщения с неподтверждённой отправкой. Если отчёта ещё нет, сообщает время его выхода |
| /search запрос | Раздел 16.4 |
| /settings | Текущие значения четырёх настроек и кнопки изменения (раздел 16.5) |
| /feedback | Запрашивает текст отзыва о качестве подбора. Отзыв можно привязать к вакансии из последнего отчёта или оставить общим |
| /stats | Статистика за 7 и 30 дней: собрано, показано, по категориям, отмечено «интересно», «откликнулся», «отклонено» с разбивкой причин; отдельной строкой — блок по заголовку. Все показатели приводятся раздельно по типам предложения: работа, стажировка, разовый проект. Кнопки «Интересные» и «Отклики» открывают списки |
| /status | Состояние источников (режим, последний успех), задач (последний запуск, ошибки), бюджет (расход, резерв, остаток), число вакансий в очередях, версия профиля и правил, ход пересчёта |

### 16.3. Кнопки карточки

| Кнопка | Действие |
|--------|----------|
| Интересно | Событие `interested` |
| Откликнулся | Событие `applied` |
| Отклонить | Запрос причины: не тот стек, уровень, не удалённо, компания, продажи, условия, уже видел, другое. Затем событие `rejected` |
| Письмо | Раздел 17 |
| Подробнее | Подробный вид (раздел 13.3) |
| Пересмотреть | Раздел 18 |

Отметку можно снять кнопкой «Снять отметку»: создаётся событие `cleared`, прежние события сохраняются.

### 16.4. Поиск

1. Бот подтверждает запрос и сообщает, что поиск начат.
2. Сразу показывает до 10 результатов из базы: полнотекстовый поиск по названию, компании и описанию среди вакансий с действующей оценкой, по убыванию балла. Отклонённые фильтрами не показываются, если не запрошено обратное кнопкой.
3. Параллельно выполняет запрос к источникам, поддерживающим поиск. Новые находки проходят обычный конвейер, включая дедупликацию.
4. На анализ новых находок расходуется не более 20 вызовов LLM. Вызовы подчиняются общему бюджету.
5. По завершении приходит второе сообщение с новыми результатами. Если лимит 20 вызовов или бюджет исчерпан, показываются уже найденные результаты и предупреждение с причиной.

Ограничения: одновременно выполняется один поиск; второй запрос получает ответ «предыдущий поиск ещё выполняется». Поиск использует отдельную задачу и не берёт блокировок сбора и отчёта. Результаты поиска — это отчёт вида `search`. Показ в результатах поиска не ставит отметку о показе в основном блоке и не влияет на ежедневный отчёт.

### 16.5. Настройки

| Настройка | Ввод | Подтверждение |
|-----------|------|---------------|
| Порог показа | Число 50–90 | «Порог показа: N. Действует со следующего отчёта» |
| Максимум карточек | Число 1–15 | «Карточек в отчёте: N» |
| Время отчёта | ЧЧ:ММ с шагом 5 минут | «Отчёт будет приходить в ЧЧ:ММ по времени Грузии» |
| Пауза | Включить или выключить | «Отчёты приостановлены» или «возобновлены». Сбор и обработка при паузе продолжаются |

Значение вне диапазона отклоняется с указанием допустимых границ. Прежнее значение сохраняется.

### 16.6. Фильтр по типу предложения

В /today, /stats, списках «Интересные» и «Отклики» и в результатах поиска есть кнопки: «Все», «Работа», «Стажировки», «Проекты». Фильтр меняет только показ: он не влияет на отбор в ежедневный отчёт, на лимит карточек и на сортировку. Три типа предложений участвуют в общей сортировке по баллу и делят общий лимит основного блока (от 1 до 15). Отдельных лимитов и отдельных конвейеров для типов нет.

## 17. Письма и ответы работодателю

| Параметр | Значение |
|----------|----------|
| Запуск | Только кнопкой «Письмо» или «Ответ на вопрос» |
| Модель | Задаётся в `llm.yaml`. По умолчанию Claude Haiku 5.5, идентификатор `claude-haiku-5-5`. Другая модель включается только ручной правкой конфигурации |
| Входные данные | Текст вакансии, извлечённые факты, текущая версия профиля, особые требования к отклику |
| Источник сведений о кандидате | Только текущая версия профиля. Контакты подставляются из профиля при формировании сообщения и в промпте не содержатся |
| Длина | До 1200 знаков |
| Варианты | До 3 на вакансию. Каждый сохраняется в `cover_letters` |
| Отправка | Только владельцу в Telegram, отдельным сообщением без комментариев внутри текста. Работодателю система ничего не отправляет |

Правила содержания:

| Правило | Содержание |
|---------|-----------|
| Позиционирование | «Python-разработчик и тестировщик (QA)». Без слов Junior, «начинающий», «начального уровня» |
| Достоверность | Только подтверждённые навыки, проекты и результаты из профиля. Коммерческий опыт и достижения не придумываются. Навыки со статусом «требует подтверждения» не упоминаются |
| Контакты | Все четыре контакта из профиля |
| Формат работы | Не упоминается и не спрашивается |
| Место нахождения | Указывается, только если вакансия прямо этого требует |
| Языки | Английский и другие языки как вариант общения не предлагаются |
| Государственный API | Проект подаётся как интеграция с государственным API |
| Соответствие вакансии | Письмо опирается на совпавшие навыки и задачи из оценки и не обещает недостающего |

Обращение с текстом вакансии:

- текст вакансии — данные. Инструкции из него не исполняются;
- особые требования к отклику (кодовое слово, вопросы, форма) показываются владельцу отдельной строкой над письмом: «Работодатель просит: …». В письмо они включаются, только если это безвредное требование к содержанию отклика;
- текст, обращённый к ИИ, показывается владельцу с пометкой «в вакансии есть обращение к ИИ» и в письме не исполняется.

Ответ на вопрос работодателя: владелец нажимает кнопку и присылает текст вопроса. Ответ строится по тем же правилам и сохраняется с видом `answer`.

При исчерпании бюджета кнопка отвечает сообщением о причине и дате сброса лимита.

## 18. Ручной пересмотр оценки

| Действие | Что происходит | Влияние на отчёт |
|----------|----------------|------------------|
| Свой балл | Владелец задаёт балл 0–100 | Балл используется при отборе, если вакансия в окне первого показа |
| Вернуть в подборку | Вакансия считается подходящей независимо от балла и фильтров | Если вакансия в окне первого показа и не показывалась, она войдёт в ближайший отчёт. Иначе карточка показывается сразу в ответ на действие, в ежедневный отчёт не попадает |
| Убрать | Вакансия исключается из отбора | Не попадает в отчёты |
| Фильтр ошибся | Указывается фильтр, сработавший неверно | Фильтр считается пройденным для этой вакансии |

Правила:

- правка хранится отдельно от расчёта и имеет приоритет. Расчётная оценка не изменяется;
- правка не меняет дату первой полной оценки и отметку о показе;
- пересчёт оценок правки не отменяет;
- правку можно отменить. Отменённая остаётся в истории;
- карточка с действующей правкой помечается «оценка изменена вручную» с показом расчётного балла;
- правки «фильтр ошибся» и причины отклонения раз в месяц сводятся в отчёт для калибровки правил. Автоматически правила не меняются.

## 19. Пересчёт оценок

| Параметр | Значение |
|----------|----------|
| Причина запуска | Новая версия профиля, словаря навыков или правил скоринга |
| Охват | Все вакансии с сохранённым текстом и извлечением, включая предварительные оценки, без ограничения по возрасту |
| LLM | Не вызывается |
| Пакет | 200 оценок в одной транзакции, пауза 1 секунда между пакетами |
| Порядок | От свежих к старым по дате первого обнаружения |
| Прогресс | Необработанные оценки остаются в состоянии «ожидает пересчёта». После перезапуска задача продолжает с них |
| Приоритет задач | Сбор, обработка, отчёт и команды бота имеют приоритет. Пересчёт не берёт их блокировок. В течение 15 минут до времени отчёта новые пакеты не начинаются |
| Отчёт во время пересчёта | Использует оценку в состоянии «ожидает пересчёта» с пометкой в подробном виде |
| Ошибка | Оценка получает состояние «ошибка пересчёта», прежний расчёт действует. Повтор при следующем запуске. После 3 ошибок подряд по одной вакансии владелец получает оповещение |
| История | Прежняя оценка получает состояние «устаревшая» и сохраняется |
| Влияние на отчёт | Пересчёт не меняет даты и отметки раздела 14.1. Старые вакансии в ежедневный отчёт не возвращаются |
| Завершение | Владелец получает сообщение: сколько оценок пересчитано, сколько изменило категорию, сколько ошибок |

Смена версии промпта или модели извлечения пересчётом не является: она действует на новые вакансии. Повторное извлечение для уже обработанных выполняется только по команде владельца и расходует бюджет.

## 20. Тихий сбор и пересмотр источников

Правила сроков и порогов — в SOURCES.md, разделы 4.4 и 4.5. Здесь — как считаются показатели.

Контроль источников состоит из трёх независимых механизмов:

| Механизм | Что делает | Шаг плана |
|----------|-----------|-----------|
| Оперативное состояние | Ошибки, повторы, деградация, отключение при запрете, оповещения, отображение в /status. Ведёт счётчики публикаций и реальных IT-предложений | A3 (счётчик предложений — A5) |
| Проверка качества каналов | Оценка периода тихого сбора, запись в `source_checks`, решение о включении, продлении или отказе | B5 |
| Пересмотр активных источников | Раз в 30 дней: перевод на повторную проверку при падении качества | C1 |

До шага B5 режим канала меняет владелец в `sources.yaml`, опираясь на счётчики в /status.

| Показатель | Как считается |
|------------|---------------|
| Публикаций за период | Все посты источника не старше 14 дней на момент сбора, кроме точных дублей внутри источника |
| Реальная IT-вакансия | Пост прошёл правила до LLM, извлечение вернуло «это предложение работы» (любого из трёх типов) и направление «основное» или «смежное». Направление «прочее» не учитывается. Жёсткие фильтры и балл не учитываются |
| Посты сверх лимита LLM | После 30 постов канала за период остальные оцениваются только правилами до LLM. Доля реальных вакансий считается по выборке из 30 |
| Прошли фильтры профиля | Из реальных IT-вакансий те, что прошли жёсткие фильтры. Справочный показатель, на решение не влияет |
| Релевантность | Реальные IT-вакансии к числу оценённых постов, в процентах |

Вакансии из источника в тихом режиме проходят конвейер, но помечены и в отчёт не попадают. После включения канала в отчёт попадают только новые вакансии: накопленные за время проверки не показываются, но доступны через /search.

Решение по итогам периода принимается задачей пересмотра источников и записывается в `source_checks`. Владелец получает сводку и может отменить решение командой.

## 21. Бюджет LLM

Механизм резервирования описан в ARCHITECTURE.md, раздел 8, и DATABASE_SCHEMA.md, раздел 9. Все значения этого раздела — значения по умолчанию из `llm.yaml`.

### 21.1. Модели

| Роль | Модель по умолчанию | Примечание |
|------|---------------------|-----------|
| Извлечение фактов и классификация | Claude Haiku 5.5, `claude-haiku-5-5` | |
| Сопроводительные письма | Claude Haiku 5.5, `claude-haiku-5-5` | |
| Ответы работодателю | Claude Haiku 5.5, `claude-haiku-5-5` | |

На старте используется одна модель. Claude Sonnet 5.5 (`claude-sonnet-5-5`) может быть назначен роли только ручной правкой `llm.yaml` владельцем. Система никогда не меняет модель сама: ни при ошибке, ни при длинном тексте, ни при низкой уверенности. Для каждой роли в `llm.yaml` заданы идентификатор модели, версия промпта, цены за миллион входных и выходных токенов и дата проверки цен. Цены на 12.11.2026: Haiku 5.5 — $0,10 и $0,50; Sonnet 5.5 — $2 и $10. При смене модели извлечения меняется ключ кэша.

### 21.2. Лимиты

| Параметр | Значение |
|----------|----------|
| Жёсткий месячный лимит | $3,00 |
| Предупреждения | При расходе $1,50 и $2,50, по одному разу за месяц |
| Резерв под письма и ответы | $0,30 недоступны для извлечения |
| Суточный лимит на извлечение | $0,08 |
| Лимит на проверку каналов | $0,50 в месяц, не более 30 постов на канал за период |
| Лимит одного поиска | 20 вызовов |
| Сброс | В первый день месяца по UTC |
| Целевой ориентир | $0,50–2 в месяц при обычном объёме. Ориентир, не гарантия |

Проверка при загрузке конфигурации: сумма резерва под письма и лимита на проверку каналов меньше месячного лимита; пороги предупреждений меньше месячного лимита.

### 21.3. Что исключает скрытое превышение

| Риск | Мера |
|------|------|
| Параллельные запросы | Резерв берётся в транзакции с блокировкой строки месяца; база отклоняет запись, где расход плюс резерв больше лимита |
| Повторные попытки | Каждая попытка — отдельный резерв. Не более 3 попыток на запись |
| Длинные описания | Каждая часть — отдельный вызов с отдельным резервом. Не более 4 частей на запись |
| Неточная оценка токенов | Верхняя граница входа: один токен на знак запроса по цене записи в кэш (самая высокая цена входа). Верхняя граница выхода: `max_tokens` по цене выхода. Фактическая стоимость не может превысить резерв |
| Остановка процесса во время вызова | Незакрытый резерв списывается как расход по верхней границе |
| Изменение цен | Цены хранятся с датой проверки. Раз в месяц владелец получает напоминание сверить их |
| Расхождение с данными поставщика | В ежемесячной сводке расход по журналу сравнивается с расходом из консоли API, если владелец его внёс |

### 21.4. Ограничения одного вызова и длинные тексты

| Роль | Вход | Выход |
|------|------|-------|
| Извлечение | Одна часть текста до 6000 знаков | `max_tokens` 3000, включая рассуждения. Уровень effort `low` |
| Письмо и ответ | Название, факты, сопоставление, профиль, первые 6000 знаков описания | `max_tokens` 2500, включая рассуждения. Уровень effort по умолчанию |

Точные параметры вызова API — в AGENT_PROMPTS.md, раздел 2. Ответ с признаком отказа модели или обрезанный по `max_tokens` считается недействительным; токены за него оплачиваются и учитываются.

Правила для длинных описаний:

- исходный текст всегда хранится полностью;
- текст длиннее 6000 знаков делится на части по границам абзацев с перекрытием 300 знаков;
- не более 4 частей на запись. Если текст длиннее, остаток не анализируется, и это явно записывается и показывается в подробном виде: «проанализировано N из M знаков». Молчаливого обрезания нет;
- результаты частей объединяет код по правилам AGENT_PROMPTS.md, раздел 5.4;
- при нехватке бюджета или перезапуске обработка продолжается с первой необработанной части;
- для письма длинный текст не делится: владелец получает пометку, что в запрос вошли факты и первые 6000 знаков.

### 21.5. Учёт фактического расхода

- Для каждого вызова в журнал записываются четыре вида токенов из ответа API: обычный вход, запись в кэш, чтение из кэша, выход, а также причина завершения и фактическая стоимость по четырём ценам.
- /status показывает расход за месяц и за сутки, средний расход на запись и на письмо, число вызовов.
- После первой недели работы суточный лимит и ожидаемый месячный расход уточняются по журналу.
- Неизменная часть запроса помечается для кэширования на стороне API. Экономия не гарантирована и в бюджет не закладывается: фактическая доля чтений из кэша показывается в /status и в ежемесячной сводке.

### 21.6. Порядок расходования

При нехватке суточного лимита: сначала записи активных источников, от свежих к старым; затем проверка каналов. Записи, не получившие вызов, остаются в `pending_llm` и обрабатываются на следующий день, если не вышли за 14 дней с публикации.

### 21.7. Поведение при исчерпании

| Что исчерпано | Что прекращается | Что продолжает работать | Сообщение |
|---------------|------------------|--------------------------|-----------|
| Суточный лимит извлечения | Извлечение до следующих суток | Всё остальное, включая письма | Строка в сводке отчёта |
| Доступная извлечению часть месячного лимита | Извлечение до конца месяца | Сбор, правила, оценка по заголовку, пересчёт, отчёт по оценённым, письма в пределах резерва | Оповещение и строка в сводке |
| Жёсткий месячный лимит $3 | Все новые платные вызовы | Сбор, дедупликация, правила, оценка по заголовку, пересчёт, отчёт, все команды, кроме генерации писем | Оповещение, /status, ответ кнопки «Письмо» с датой сброса |

## 22. Обработка ошибок

| Ошибка | Реакция системы | Сообщение владельцу |
|--------|-----------------|----------------------|
| Сетевая ошибка, 429, 5xx у источника | До 3 повторов с нарастающей паузой. Курсор не сдвигается | Нет. После 5 сбоев подряд — одно оповещение |
| 403, капча, требование входа | Источник отключается до решения владельца | Сразу |
| Разбор вернул ноль записей 3 запуска подряд | Источник помечается деградировавшим | Одно оповещение |
| Запись источника не проходит нормализацию | Запись сохраняется в `raw_items`, вакансия не создаётся, ошибка в журнал | В /status счётчик. Оповещение, если доля превышает 20 % за запуск |
| LLM недоступна или вернула ошибку | Резерв закрывается по правилам, попытка засчитывается. Повтор в следующем запуске обработки | После 3 запусков подряд без успешных вызовов |
| Ответ LLM не проходит схему | Одна повторная попытка. Затем статус `llm_failed` | В /status счётчик |
| Цитата не найдена в тексте | Факт понижается до «неизвестно» | Нет. Счётчик в подробном виде |
| Бюджет исчерпан | Раздел 21 | По таблице раздела 21 |
| Telegram отклонил сообщение | Повтор до 5 раз, затем `failed` | В сводке следующего отчёта |
| Исход отправки неизвестен | `unconfirmed`, без повтора | Число в сводке, карточка в /today |
| База недоступна | Задачи завершаются с ошибкой, повтор по расписанию. Бот отвечает «временная ошибка» | Через внешний пульс |
| Ошибка в задаче планировщика | Запись в `job_runs`, задача запускается по расписанию снова | Одно оповещение на тип ошибки в час |
| Не удалось получить описание для `awaiting_description` | Статус сохраняется, причина записывается, повтор не чаще раза в сутки | В /status счётчик |
| Файл конфигурации не проходит проверку | Изменение не применяется, действует прежняя версия | Сразу, с указанием поля |
| Процесс остановился | Перезапуск контейнера, восстановление по ARCHITECTURE.md, раздел 12 | Внешний пульс при простое более 30 минут |

Общее правило: ошибка одной вакансии или одного источника не останавливает обработку остальных.

## 23. Логирование и оповещения

| Тема | Правило |
|------|---------|
| Формат | Структурированные записи: время, уровень, компонент, событие, идентификаторы источника, вакансии, запуска |
| Что пишется | Запуск и итог каждой задачи; каждый запрос к источнику (адрес без параметров доступа, код ответа, длительность); каждый вызов LLM (роль, модель, токены, стоимость, исход); смена статуса вакансии; отправка сообщений; действия владельца |
| Чего в логах нет | Секретов и ключей; полного текста вакансий, ответов LLM и писем; содержимого сообщений владельца сверх команды |
| Уровни | Информация — штатные события; предупреждение — повтор, понижение факта, деградация; ошибка — сбой задачи или источника |
| Хранение | Стандартный вывод контейнера, ротация 5 файлов по 10 МБ |
| Оповещения | В Telegram владельцу, через `outbox`. Не более одного сообщения на тип ошибки в час. Ночью с 23:00 до 07:00 по времени Грузии — без звука |
| Внешний пульс | Сигнал каждые 15 минут. Сервис-сторож оповещает при отсутствии сигнала 30 минут |
| Ежемесячная сводка | Расход бюджета, качество источников, частые неизвестные навыки, ручные правки и причины отклонений |

## 24. Критерии приёмки MVP

### 24.1. Технические

Критерии приёмки обозначаются ACC-1…ACC-12 и не совпадают с номерами шагов разработки A1–A8. Критерии качества подбора обозначаются QLT-1 и QLT-2.

| № | Критерий | Способ проверки |
|---|----------|-----------------|
| ACC-1 | Отчёт приходит вовремя 7 дней подряд | Время отправки сводки не позже 5 минут после заданного |
| ACC-2 | Ни одного повторного уведомления | Сверка `outbox` и полученных сообщений за 7 дней |
| ACC-3 | Ни одна вакансия не показана в основном блоке дважды | Запрос по `report_items` |
| ACC-4 | Перезапуск во время сбора, обработки и отправки отчёта не приводит к потере данных и дублям | Три ручные остановки контейнера в разных фазах |
| ACC-5 | Бюджет не превышается при параллельных запросах | Тест: 50 одновременных резервирований при остатке на 10 |
| ACC-6 | При исчерпанном бюджете отчёт выходит, причина указана | Тест с лимитом, установленным в ноль |
| ACC-7 | Сбой одного источника не влияет на отчёт | Отключение источника в конфигурации теста |
| ACC-8 | Бот отвечает на команды за 3 секунды во время сбора и пересчёта | Замер времени ответа |
| ACC-9 | Посторонний пользователь не получает ответа | Сообщение с другого аккаунта |
| ACC-10 | Восстановление базы из резервной копии | Развёртывание дампа в пустую базу |
| ACC-11 | Пересчёт после смены профиля сохраняет историю и не возвращает старые вакансии в отчёт | Изменение профиля в тесте, проверка следующего отчёта |
| ACC-12 | Все автотесты проходят | Запуск набора тестов |

### 24.2. Качество подбора

| Параметр | Значение |
|----------|----------|
| Объём выборки | 40 вакансий из собранных системой |
| Разметка | Выполняется владельцем вручную до сравнения с результатами системы. Категории: «подходит», «можно рассмотреть», «не подходит» |
| Состав | Не менее 5 разовых проектов. Основные направления: Python и backend, Telegram-боты, AI-интеграции, QA. Разные источники. Разные требования к стажу: без опыта, 1–3 года, 3–5 лет, 5 и более. Пограничные случаи: слово уровня без стажа, неизвестная география, желательный английский, доля продаж, пост не является вакансией |
| Соответствие категорий | «Подходит» — балл от 70; «можно рассмотреть» — 50–69; «не подходит» — ниже 50 или исключено фильтром |
| Критерий QLT-1 | Ни одна вакансия с отметкой «подходит» не исключена правилами или фильтрами |
| Критерий QLT-2 | Категория системы совпадает с категорией владельца не менее чем в 80 % случаев (не менее 32 из 40) |
| При невыполнении | Разбор расхождений, правка правил или словаря, новая версия правил, повторная проверка на той же выборке |

Выборка сохраняется и используется как постоянный эталон при каждом изменении правил и промпта.
